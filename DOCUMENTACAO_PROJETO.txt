1. IDENTIFICAÇÃO E OBJETIVO
---------------------------
Nome técnico do assembly: ProtetorDigital
Projeto: ProtetorDigital
Tipo: aplicação desktop Windows Forms
Target framework: .NET 10 para Windows (net10.0-windows)
Namespace principal: ProtetorDigital

--------------------------
O ProtetorDigital.csproj define:

- UseWindowsForms true;
- Nullable enable;
- ImplicitUsings enable;
- RootNamespace ProtetorDigital;

Não há pacote NuGet adicional declarado no projeto. A desserialização usa System.Text.Json, incluído no .NET.

O projeto possui recursos .resx para telas e imagens. A classe Properties.Resources é gerada para acesso aos recursos incorporados.


4. FLUXO PRINCIPAL DA APLICAÇÃO
--------------------------------
Program.cs é o ponto de entrada. O método Main inicializa a configuração padrão do Windows Forms e abre FrmMenu.

Fluxo de telas:
1. FrmMenu é a tela inicial.
2. O botão Quiz abre FrmQuiz e oculta o menu.
3. O botão Biblioteca abre FrmBiblioteca e oculta o menu.
4. FrmBiblioteca abre uma das telas de conteúdo:
   - FrmDicas;
   - FrmRelatos;
   - FrmExGolpes.
5. As telas filhas são abertas modalmente pelo menu ou pela biblioteca.
6. O botão Sair chama Application.Exit().

O padrão atual de navegação usa `Hide()`, `ShowDialog(this)`, `Show()` e `Close()`. A janela filha não mantém referência própria à origem; o método que abriu o diálogo aguarda seu fechamento e reexibe a tela anterior.


5. MODELOS DE DADOS
-------------------

Models/Dica.cs
Representa uma dica educativa:
- Id: identificador numérico;
- Titulo: título;
- Descricao: explicação;
- PassosRecomendados: lista de orientações.
O campo passos_recomendados do JSON é mapeado para PassosRecomendados com JsonPropertyName.

Models/ExGolpe.cs
Representa um exemplo de golpe:
- Id;
- NomeGolpe, mapeado de nome_golpe;
- ComoFunciona, mapeado de como_funciona;
- SinaisDeAlerta, mapeado de sinais_de_alerta.

Models/Relato.cs
Representa um caso noticiado:
- Id;
- Titulo;
- Fonte;
- Vitima;
- Conteudo, mapeado de relato;
- LicoesAprendidas, mapeado de licoes_aprendidas.

Models/Pergunta.cs
Representa uma questão do quiz:
- Id;
- Texto, mapeado de pergunta;
- Opcoes: lista de alternativas;
- RespostaCorreta: posição original da resposta correta, usando numeração iniciada em 1;
- Explicacao.

As propriedades textuais são nullable. As telas usam valores vazios ou listas vazias como fallback para evitar falhas de UI quando um campo estiver ausente.


6. ARQUIVOS JSON E FORMATO DE CONTEÚDO
--------------------------------------

 dados/dicas.json
- Objeto raiz com a propriedade categoria.
- Os registros ficam dentro da propriedade itens.
- Cada item contém id, titulo, descricao e passos_recomendados.
- É consumido por FrmDicas.

 dados/exgolpes.json
- Objeto raiz com categoria.
- Os registros ficam em itens.
- Cada item contém id, nome_golpe, como_funciona e sinais_de_alerta.
- É consumido por FrmExGolpes.

 dados/relatos.json
- Objeto raiz com categoria.
- Os registros ficam em itens.
- Cada item contém id, titulo, fonte, vitima, relato e licoes_aprendidas.
- É consumido por FrmRelatos.

 dados/perguntas.json
- Array JSON diretamente na raiz.
- Cada pergunta contém id, pergunta, opcoes, respostaCorreta, explicacao e explicacaoOpcoesErradas no conteúdo atual.
- FrmQuiz desserializa o array diretamente em List<Pergunta>.
- A classe Pergunta atualmente não possui uma propriedade para explicacaoOpcoesErradas; esse campo extra é ignorado pelo System.Text.Json.
- O arquivo foi corrigido anteriormente: havia um caractere extra S depois do fechamento do array (final ]S), causando erro de JSON. O final correto passou a ser apenas ].

Regra importante: alterações de conteúdo devem preservar o formato esperado pela tela correspondente. JSONs com raiz objeto precisam manter a propriedade itens; perguntas precisam manter a raiz como array.


7. IMPLEMENTAÇÃO DAS TELAS
---------------------------

FrmMenu
- Inicializa a tela principal.
- BtnQuiz abre o quiz.
- BtnBiblioteca abre a biblioteca.
- BtnSair encerra a aplicação.

FrmBiblioteca
- Funciona como menu de conteúdos.
- BtnDicas abre FrmDicas.
- BtnRelatos abre FrmRelatos.
- BtnExGolpe abre FrmExGolpes.
- BtnVoltar exibe a janela de origem e fecha a atual.

FrmDicas
- Carrega dados/dicas.json.
- Procura primeiro em bin/Debug/.../dados e depois usa fallback para ../../../../dados a partir da base de execução.
- Faz JsonDocument.Parse, obtém itens e desserializa List<Dica>.
- Mostra uma dica por vez.
- BtnAvancar navega para o próximo item.
- BtnVoltar navega para o item anterior ou fecha a tela no primeiro item.
- Os passos são apresentados como linhas iniciadas por hífen.
- O tratamento de erro atual ignora falhas de leitura para não interromper a UI.

FrmExGolpes
- Tem fluxo equivalente ao de FrmDicas.
- Carrega dados/exgolpes.json e desserializa List<ExGolpe> a partir de itens.
- Exibe nome do golpe, funcionamento e sinais de alerta.
- Permite avançar, voltar e retornar à biblioteca.

FrmRelatos
- Carrega dados/relatos.json e desserializa List<Relato> a partir de itens.
- Exibe título, fonte, vítima, relato e lições aprendidas.
- Mantém os botões de avanço e retorno habilitados conforme o índice atual.
- Permite voltar à biblioteca pelo botão de retorno.

FrmQuiz
- Carrega dados/perguntas.json.
- Usa JsonSerializer.Deserialize<List<Pergunta>> com PropertyNameCaseInsensitive = true.
- Exibe uma pergunta e quatro RadioButtons.
- Confirma a resposta, calcula pontuação e mostra feedback.
- Ao terminar, mostra a quantidade de acertos e retorna à janela de origem.
- As alternativas são embaralhadas na memória somente no momento da exibição.
- O JSON não é alterado pelo embaralhamento.
- A alternativa correta é marcada antes da ordenação aleatória e sua nova posição é armazenada em _respostaCorretaExibida. Assim, a validação continua correta mesmo quando a alternativa muda de posição.
- _opcoesExibidas guarda a ordem mostrada ao usuário.


8. ALTERAÇÕES JÁ REALIZADAS E MOTIVAÇÃO
---------------------------------------

A. Correção do JSON de perguntas
Problema original:
- O parser acusava: 'S' is invalid after a single JSON value. Expected end of data.
- O erro apontava para $[10], linha 181/182, posição inicial da linha.

Causa:
- Havia conteúdo extra depois do array: ]S.
- O array já estava fechado em ], portanto o S não pertencia a nenhum valor JSON válido.

Como deveria ser:
- O arquivo deveria terminar no fechamento do array, com ] e nada depois, exceto espaços ou quebra de linha.

Como ficou:
- O caractere S foi removido.
- As 10 perguntas válidas foram preservadas.
- FrmQuiz.cs não precisou ser alterado para resolver o erro de sintaxe.

B. Embaralhamento das alternativas
Necessidade:
- Apresentar as alternativas em ordem diferente a cada abertura/exibição do quiz sem modificar o arquivo de dados.

Como deveria ser:
- Copiar as alternativas para uma estrutura em memória.
- Associar cada alternativa à indicação de correta/incorreta.
- Embaralhar a cópia.
- Validar a escolha pela nova posição, não pela posição original do JSON.

Como ficou:
- FrmQuiz.cs cria opcoesComResposta usando Select.
- A ordenação usa OrderBy(_ => Random.Shared.Next()).
- _opcoesExibidas recebe a ordem embaralhada.
- _respostaCorretaExibida recebe o novo índice correto.
- O JSON continua com a ordem original.
- O feedback usa as alternativas na ordem exibida.

C. Renomeação do projeto e solução
Problema original:
- O projeto estava nomeado como p2elvio, sem relação com o nome técnico ProtetorDigital.

Como ficou:
- O nome do projeto e da solução foi alterado para ProtetorDigital.
- RootNamespace e AssemblyName permanecem como ProtetorDigital, sem necessidade de alteração.

Motivação:
- O novo nome é mais condizente com a finalidade do projeto e facilita a identificação do assembly gerado.

9. PADRÕES DE CARREGAMENTO DE DADOS
-----------------------------------
Todas as telas que carregam JSON usam `ConteudoService`, que procura o arquivo em `AppDomain.CurrentDomain.BaseDirectory/dados/<arquivo>`.

O `.csproj` copia explicitamente os arquivos de `dados` para a saída, portanto não existe fallback para `..\..\..`.


10. COMO O PROJETO FOI FEITO E POR QUÊ
--------------------------------------
A aplicação foi estruturada com Windows Forms por ser uma solução desktop simples, visual e adequada para navegação por botões e controles tradicionais.

A separação adotada foi:
- Forms para interface e eventos;
- Models para representar os dados;
- JSON para manter o conteúdo educativo fora do código;
- resx/imagens para recursos visuais e layout criado pelo Designer.

Essa separação permite alterar textos, dicas, relatos e perguntas sem recompilar a lógica, desde que o formato dos dados seja preservado.

A navegação entre telas usa diálogos modais porque o fluxo é pequeno e linear. O quiz mantém estado local de índice e pontuação porque seu ciclo é independente da biblioteca.


10.1. GUIA DE MECÂNICAS DO CÓDIGO PARA ESTUDO
----------------------------------------------
Esta seção explica como as principais partes do código trabalham juntas.

Inicialização da aplicação
- `Program.cs` contém o método `Main`, marcado com `[STAThread]`, requisito padrão para aplicações Windows Forms.
- `ApplicationConfiguration.Initialize()` aplica as configurações padrão do Windows Forms, incluindo temas e DPI.
- `Application.Run(new FrmMenu())` cria o menu principal e mantém o loop de mensagens da aplicação ativo. Esse loop recebe cliques, teclado, pintura e fechamento das janelas.

Formulários e arquivos Designer
- Cada tela é dividida em um arquivo de lógica (`.cs`) e um arquivo parcial gerado pelo Designer (`.Designer.cs`).
- O Designer cria controles, define propriedades visuais e conecta eventos como `Click`.
- A lógica dos eventos fica no arquivo `.cs`; por isso, alterações de comportamento devem ser feitas ali sempre que possível.
- `InitializeComponent()` deve ser chamado no construtor antes de usar os controles.

Modelos e desserialização
- As classes em `Models` representam o formato dos objetos JSON e são usadas como tipos genéricos pelo carregador.
- Propriedades nullable, como `string?`, indicam que um campo pode estar ausente. As telas convertem esses valores para texto vazio quando necessário para evitar falhas de UI.
- `JsonPropertyName` conecta nomes diferentes entre código e JSON, como `pergunta`/`Texto`, `relato`/`Conteudo` e `licoes_aprendidas`/`LicoesAprendidas`.

Carregamento centralizado de conteúdo
- `Services/ConteudoService.cs` concentra a leitura dos arquivos na pasta `dados` do diretório de execução.
- `CarregarLista<T>` permite reutilizar a mesma mecânica para dicas, golpes, relatos e perguntas.
- O método aceita tanto um array JSON na raiz quanto um objeto que contenha a propriedade `itens`.
- `Encoding.UTF8` garante a leitura correta de acentos.
- Falhas de arquivo, permissão, JSON inválido ou estrutura incompatível são convertidas em `ConteudoException`, cuja mensagem cita o nome do arquivo.
- Cada formulário captura essa exceção, mostra uma mensagem simples ao usuário e fecha a janela para retornar ao fluxo anterior.

Eventos e ciclo de vida das telas
- O evento `Load` é usado para carregar o conteúdo quando a tela está prestes a ser exibida.
- Eventos `Click` respondem aos botões e chamam métodos de navegação ou atualização da tela.
- Eventos `KeyDown`, combinados com `KeyPreview = true`, permitem tratar Esc e as setas mesmo quando o foco está em outro controle.
- Fechar uma janela modal libera o controle para o método que chamou `ShowDialog`.

Navegação modal
- O menu oculta a si mesmo com `Hide()` antes de abrir Quiz ou Biblioteca.
- A janela filha é aberta com `ShowDialog(this)`, tornando-a modal e mantendo o fluxo aguardando seu fechamento.
- Depois que a janela filha fecha pelo botão, pelo Esc ou pelo X, o método retorna e executa `Show()` para reexibir a origem.
- O menu usa `Application.Exit()` no botão Sair; assim, sair pelo menu encerra a aplicação inteira.
- As telas de leitura mantêm um índice (`_indice`) e só habilitam Anterior quando existe item anterior e Avançar quando existe item seguinte.

Exibição das telas de leitura
- `MostrarDica`, `MostrarGolpe` e `MostrarRelato` recebem um índice, validam seus limites e copiam os campos do modelo para os labels.
- Listas como passos recomendados e sinais de alerta são convertidas em texto com uma linha iniciada por hífen.
- O índice atual é atualizado antes de recalcular o estado dos botões.
- Setas esquerda/direita chamam o mesmo método usado pelos botões, evitando duplicação da regra de navegação.
- Em relatos, o tipo `ilustrativo` controla a exibição da etiqueta que informa que o caso é baseado em modalidades reais.

Mecânica do Quiz
- `_indiceAtual` identifica a pergunta mostrada e `_pontuacao` guarda a quantidade de acertos.
- Ao exibir uma pergunta, cada alternativa é associada ao seu índice original por `OpcaoExibida`.
- `Random.Shared.Shuffle` embaralha somente a cópia em memória; o JSON permanece inalterado.
- `_respostaCorretaExibida` localiza a posição atual da resposta cujo índice original corresponde a `RespostaCorreta`.
- A confirmação identifica qual RadioButton está marcado, compara sua posição exibida com a posição correta e bloqueia as alternativas após o feedback.
- `ExplicacaoOpcoesErradas` é consultada pelo índice original da alternativa escolhida, garantindo que a explicação continue correta depois do embaralhamento.
- `LimparPrefixo` remove os marcadores editoriais `Errado!` e `Correta!` antes de exibir a explicação.
- O painel de feedback muda entre verde e vermelho, conforme o resultado, sem abrir uma segunda tela ou MessageBox para o feedback.
- A ProgressBar e o label de progresso usam o índice atual para mostrar “Pergunta X de N”.
- Após a última confirmação, `MostrarResultado` apresenta o total, uma mensagem por faixa de desempenho e as perguntas erradas com a resposta correta.
- `Refazer` limpa pontuação e erros, volta ao primeiro item e embaralha novamente as alternativas. `Voltar ao menu` fecha o diálogo do quiz.

Projeto, conteúdo e recursos
- O `.csproj` copia `dados\**` e `imagens\**` para a saída com `PreserveNewest`, permitindo que os arquivos externos acompanhem o executável.
- `ApplicationHighDpiMode=PerMonitorV2` permite que a interface se adapte ao monitor usado.
- Arquivos JSON são conteúdo editável; imagens e arquivos `.resx` são recursos visuais usados pelos designers.
- O conteúdo educativo não deve receber fontes, URLs, telefones ou fatos novos sem verificação. Informações pendentes devem ser registradas em `docs/RELATOS_A_VERIFICAR.md`.
